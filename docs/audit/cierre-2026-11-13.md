# Dictamen de cierre — Tukul (2026-11-13)

Skill: `criterios_de_cierre`. Modalidad: auditoría **de solo lectura** sobre el
repositorio, la CI, la Release publicada y el log real de operación, seguida de
la ejecución de las **dos condiciones** que el dictamen emitió.

## Dictamen

**CIERRE CONDICIONADO** al emitirse; condiciones **ejecutadas y verificadas** con
la release `v0.5.2`. El cierre formal depende de la evidencia de aceptación
registrada en la sección «Resolución de condiciones».

  con Python 3.11/3.12/3.13; build de release en `ubuntu-22.04` (glibc 2.35).
  Windows y macOS fuera de soporte por decisión documentada.
- **Nivel de madurez esperado:** Operativo controlado.

## Hallazgos y bloqueos

### H-C1 — [MEDIA · CONFIRMADO · NO BLOQUEANTE] La Release no cubría el último arreglo de código

- **Capacidad afectada:** consistencia de entrega (criterio 13).
- **Impacto operativo:** el binario `v0.5.1` opera, pero no incluye `7dcee7f`;
  el síntoma está confirmado en `~/.local/state/tukul/tukul.log`
  (`2026-11-12T20:44:03`, `TclError: bad window path name ".!topbar"`).
- **Evidencia:** `gh release view v0.5.1` → tag `97b62e3`; HEAD `7dcee7f`; CI
  verde en `7dcee7f` (run `43361204643`, 4 jobs `success`, `runner_name` no
  vacío, 20/20/20/10 pasos).
- **Condición de bloqueo:** no (media; coherencia de entrega, no seguridad ni
  función esencial).
- **Acción mínima:** publicar `v0.5.2` sobre `7dcee7f` con binario, `SHA256SUMS`
  y SBOM.

### H-C2 — [MEDIA · CONFIRMADO · NO BLOQUEANTE] El informe de cierre declaraba un estado ya superado

- **Capacidad afectada:** documentación y trazabilidad (criterio 14).
- **Evidencia:** `docs/audit/cierre-2026-11-12-rev2.md` afirmaba
  `git describe → v0.5.1` limpio cuando el HEAD era `v0.5.1-2-g7dcee7f`.
- **Condición de bloqueo:** no.
- **Acción mínima:** anotar el estado real y enlazar el dictamen vigente.

**CERRADO.** Las dos condiciones están cumplidas y verificadas sobre el

  proveedor, H2, AT-SPI, rotación de la key de evals) son riesgos aceptados o
  mejoras opcionales que no impiden el cierre.

## Recomendación final

Las capacidades esenciales están demostradas con evidencia real (suite completa,
binario de Release, checksums y consultas reales a las cinco fuentes externas) y
no hay bloqueos de seguridad, integridad ni de función esencial. La única
condición abierta era la alineación entre código declarado, artefacto y versión
ejecutada; con `v0.5.2` queda cerrada. Procede **congelar la versión `0.5.2` y
detener el desarrollo** de este alcance.
